- 1.2 step 3: «صنف جديد» is now the only way to add a product — the legacy panel's create form was removed and its list/edit/archive stayed; the inline «تصنيف جديد» creates a sub under the chosen counted category's main (a childless main gets its first sub); the shop code is suggested, not reserved, so two screens may be offered the same code and the second save is refused as a used barcode; a typed barcode is 6–14 digits (the mockup's rule); the price is required and above zero; no brand, reorder level, warranty or colour field was added (not in any approved proposal).
- 1.2 step 4: a variant parent (`product_parents`) has a unique name within its category (case-insensitive) and 1 or 2 dimensions from the 7 `NI_DIMS` (even if the UI leaves the second dimension's dropdown selected with no values, it is saved as 1D); each combination is a `products` row (`parent_id`, `variant_1`, `variant_2`, `variant_order`) named `${base} ${values}` by the domain (`variant_title`); max 60 combinations (`NI_MAX_VARIANTS = 60`); blank row price uses the default price above («السعر الفاضي = اللي فوق»); «اعمل أكواد للي من غير باركود» (`next_shop_codes`) fills blank rows with consecutive EAN-13 shop codes skipping stored and in-table codes; the whole family commits in one transaction; on the sales screen, variants of a parent collapse into one `.tile.fam` tile opening `VariantPickerModal` while search/barcode finds the variant itself.
- 1.2 step 5: each product has at most one 192×192 JPEG thumbnail stored on disk at `images/<product_id>.jpg` (`bytes <= 65536`), with only the relative path and metadata in `product_images` (`XC-10`); picking an image in «المخزن» centre-crops any image to 192×192 on a white background (`quality = 0.82`); for a variant family tile on the sales screen, the tile uses the image of the first variant in the family that has one; turning off «اعرض صور الأصناف» (`ui.images = 'off'`) in Settings hides images on the sales screen without deleting them (owner-only under `ManageCatalog`, no password prompt).
- `ADR-039` (أول تشغيل من غير حساب): «من غير حساب» = صف `users` واحد `provisional = 1` (مش مستخدم وهمي)، و«مفيش حساب» = الصفة دي موجودة، مش `COUNT(*) = 0` — محل ضاف بيّاع الأول يفضل مفتوح. سر الصف العشوائي بيتعمل ثم بيhash بس، ومحدش بيشوفه أصلًا، فالدخول بيه مستحيل. موافقة المالك بتتنفذ في الوضع المفتوح بتوقيع نفس الصف (مش بتتخطى)، و`Session::open` هو المُنشِئ الوحيد. كلمة السر الجديدة بتفتح الجلسة نفسها (`auth::login`) فالشاشة ما بتقفلش بعد التأسيس، وكود الاسترجاع بيتعمل في نفس اللحظة. شاشة `setup` سايبينها كـ fallback لو إنشاء الصف فشل.
- `ADR-039` (الموبايل): تخطيط الموبايل قرار عرض في `mobile.css` (مساحة عرض ≤760px أو `pointer: coarse`)، مش نوع جهاز — أي نافذة كمبيوتر ضيقة تاخد نفس التخطيط. نسخة الأندرويد لسه سيستم كامل بقاعدة بيانات على الجهاز (مش عميل للكمبيوتر)، ومفيش مزامنة: القرار ده غيّر العرض وبداية الشاشة بس. «الموبايل» (معاينة الشاشات المساعدة) بتتشال من شريط الموبايل، لأن معاينة الموبايل على الموبايل نفسها مش ليها معنى.



## 6. Approved schema proposals not built yet (ADR-016 #31; from the archived handoff §4)

Money is integer piastres throughout. Build each **as proposed**, in its own migration with checks; anything bigger goes back to the owner.

- `units(id, product_id, imei, imei2, unit_cost_minor, status, received_movement_id, sale_line_id NULL, retired_reason NULL)`, plus `sale_lines.unit_id NULL`; used-device details (grade A/B/C, battery, what comes with it, seller details optional) on the units table (1.4).

- `sale_payments(sale_id, method, amount_minor, reference NULL)` for split payments, and `customer_ledger` for آجل (1.5).
- Discount limit for sellers, owner PIN above it (1.6).
- `shifts`, `cash_movements`, `expenses` (1.9); `service_entries` (wallet / card / bill / software, `fee_minor` typed per transaction) (1.10); `wallets` (opening, min, max, daily limit, own number, pay method) and `wallet_ops` (deposit, withdraw, top-up/unload via drawer or outside, move, adjust, void with reason) — wallet balances include sales paid by that wallet's method (1.10).

- Settings: `services.fee_mode` (`manual` default | `auto`) with `fee_pct`, `fee_min_minor`, `bill_fee_minor`; `receipt.printer_enabled` (false); `receipt.default_mode`; `payments.enabled_methods`.
