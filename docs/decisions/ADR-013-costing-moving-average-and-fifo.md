# ADR-013: طرق التكلفة — المتوسط المرجح المتحرك وFIFO

**الحالة:** مقبول (accepted) — قرار المالك 2026-10-07.

**يُعدّل جزئيًا:** `ADR-002`. `ADR-002` يبقى صحيحًا في كل ما عدا رفضه لـFIFO لكل الأصناف؛ انظر «الإلغاء الجزئي» أدناه.

---

## السياق

`ADR-002` (2026-09-28) قبل **FIFO لكل الأصناف**، بسبب:

> «يعطي تكلفة كل دفعة، لكنه يفرض تتبّعًا وتخصيصًا للدفعات على كل صنف كمي، مع عبء لا يحتاجه محل واحد لكل المنتجات.»

 warehousing **جانبان** في هذا الرفض، وكلاهما محل إعادة نظر:

1. **نطاق الرفض:** كان الرفض لـFIFO **كخيار عام على كل صنف**. مواصفة التسليم الجديدة تجعل FIFO **اختياريًا على مستوى القسم**. القسم يمكن أن يختار `moving_average` كما كان، فلا يُحمَّل أي صنف كمي تتبّع دفعات لم يطلبه.
2. **عدد الأصناف:** الاعتراض الثاني — «عبء لا يحتاجه محل واحد» — كان صحيحًا كحكم على **الافتراضي**، وليس على **الإمكان**. بقاءه كخيار لا يجعله الافتراضي.

### تعارض يجب تسجيله لا تجاهله

المستودع يحمل قرارًا **مقبولًا** يرفض FIFO، ومواصفة التسليم الأحدث تعتمد FIFO وتُدرجها في قائمة «لا يجوز تأجيلها». قراران موقّعان باسم المالك يعارضان بعضهما. هذا الـADR هو التسوية: **المواصفة الأحدث تُلغي جزئيًا `ADR-002`**.

## أحكام حسابية ثابتة

هذه ليست قابلة لإعادة النظر لكل صنف؛ هي البنية التي يُبنى عليها أي محرك تكلفة.

### الطبقات (Cost Layers)

| | |
|---|---|
| **الطبقات** | حقيقة **حيث يلزم FIFO**، وقابلة لإعادة البناء من سجل الحركات |
| **المتوسط المرجح** | لا طبقات. التقييم = `total_cost_minor / on_hand` |
| **FIFO** | الاستهلاك من الأقدم: `ORDER BY created_at, id` |

### FIFO لا يحتاج تقريبًا إطلاقًا

FIFO يستهلك وحدات كاملة بتكلفة وحدة صحيحة:

```
cost_removed = Σ (layer_remaining_quantity × layer_unit_cost_minor)
```

كل المعاملات أعداد صحيحة، فالنتيجة عدد صحيح بالضبط. **صفر تقريب في FIFO.**

### المتوسط المرجح لا يحتاج عمود `cost_remainder_minor`

سؤال سابق: هل يلزم عمود remainder لمنع الانحراف التراكمي؟ **البرهان says لا**، بـ`R = 0` دائمًا.

ليكن `T = total_cost_minor`، `Q = on_hand`، `U = units` مع `1 ≤ U ≤ Q`. تحت تقريب السقف المعتمد:

```
cost_removed = ceil( U · T / Q )
```

**الدعاوى:**

1. `U·T/Q ≤ T` لأن `U ≤ Q`، و`T` عدد صحيح غير سالب، فسقف قيمة ≤ عدد صحيح لا يتجاوزه: `cost_removed ≤ T`. ومنه `new_T = T − cost_removed ≥ 0` دائمًا. **لا يمرّ الخصم تحت الصفر أبدًا.**
2. عند بلوغ `Q = 1` وبيع الوحدة الأخيرة: `U = 1`، `cost_removed = ceil(T) = T` بالضبط، فـ`new_T = 0`. **مجموع ما استُهلك عبر عمر الصنف = `T` الأصلي بالضبط.**

**النتيجة:** لا انحراف تراكمي، ولا عمود إضافي، والـreplay مطابق للـpiastre الواحد. الـremainder ثابت تحت هذا التعريف، فلا يحمل معلومة.

**الثمن المطلوب:** تقريب السقف على تكلفة المباع يخطئ هامش كل سطر بمقدار ≤ 1 piastre ويميل للربح **أقل** لا أعلى. هذا مقصود: لا ربح وهمي.

### التقريب

القرار معتمد من مواصفة التسليم (§10):

> أي كسر من الـpiastre يُقرَّب **إلى الأعلى**؛ والعدد الصحيح يبقى كما هو.

```
10.00 → 10      10.01 → 11      10.99 → 11
```

**لا** يُستبدل بـbanker's rounding أو nearest أو half-up. **لا** يتم تطبيق التقريب على قيمة مخزَّنة؛ التقريب يظهر عند الحساب فقط.

### الوسائط:i128

`units × total_cost_minor` قد يفيض `i64`. تُستخدم `i128` للوسطاء. **لا float إطلاقًا** — لا `f32` ولا `f64` ولا `REAL` ولا نص عشري.

### لقطة تكلفة البيع

سطر البيع يخزّن `unit_cost_minor` و`cost_total_minor` وقت البيع. **لا يُعاد حسابه أبدًا.** توريد لاحق أو تغيير سعر شراء **لا يغيّر ربح عملية قديمة**.

### تكلفة مرتجع العميل

يُعاد الرصيد **بتكلفة سطر البيع الأصلي**، لا بمتوسط اليوم ولا بحالة FIFO الحالية. هذا جوهر الـsnapshot: سطر البيع يحمل مرجعًا إلى تكلفته، والـmovement المرتبط به يحمل `restored_unit_cost_minor` من ذلك السطر لا من أي حساب.

### تبديل طريقة التكلفة

| | |
|---|---|
| الصلاحية | **Manager فقط**، ومع Reauthentication، ومع Pattern عند تفعيله |
| الأثر | **على العمليات الجديدة فقط**؛ لا يعيد حساب العمليات تاريخية |
| نقطة البداية | **الحالة الحالية للمخزون** |
| MA → FIFO | تُبذَر طبقة واحدة بسعر المتوسط الحالي وكمية `on_hand` الحالية |
| FIFO → MA | ينهار إلى `T / Q` |
| التسجيل | كل تبديل حدث مسجَّل في التدقيق |

## القرار

1. **طريقتان معتمدتان:** `moving_average` و`fifo`. معرَّفتان على مستوى القسم في `departments.cost_method`.
2. **FIFO متاح كخيار وليس كافتراضي.** `ADR-002` يُلغى جزئيًا في رفضه لـFIFO؛ بقية قراراته تبقى.
3. **الطبقات حقيقة** حيث يلزم FIFO، ومشتقّة من سجل الحركات.
4. **لا `cost_remainder_minor`** — الدليل أعلاه. يُضاف فقط إذا ظهر دليل جديد.
5. **تقريب السقف** عند كل كسر piastre، في الحساب لا التخزين.
6. **`i128` للوسطاء.** لا عدد عشري إطلاقًا في أي مسار مالي.
7. **لقطة تكلفة البيع دائمة.** لا إعادة حساب تاريخي.
8. **مرتجع العميل بتكلفة سطره الأصلي**، لا بحالة التكلفة الحالية.
9. **تبديل الطريقة Manager فقط، يبدأ من الحالة الحالية، ولا يعيد التاريخ.**

## البدائل التي رُفضت

### إبقاء رفض ADR-002 لـFIFO

مرفوض كـ**تجميد صامت**. المستودع كان سيحمل قرارين متعارضين موقّعين باسم المالك، بلا أي أثر يوثّق التعارض.

### FIFO كافتراضي لكل الأصناف

مرفوض. اعتراض ADR-002 الأصلي على العبء يبقى صحيحًا كحكم على **الافتراضي**.

### `cost_remainder_minor`

مرفوض بعد البرهان. عمود إضافي لا يحمل معلومة تحت هذا التعريف.

### `average_cost` مخزّن

مرفوض. القسمة عند كل استلام وب كل بيع تتراكم. حفظ **الإجمالي** يجعل القسمة مرة واحدة عند القراءة، والتقييم مشتق لا منحرف.

### nearest أو half-up

مرفوض صراحة. السقف هو القرار المعتمد.

###_float / REAL_

مرفوض. يخالف `spec:56` و`ADR-010`، ولا يمكن تمثيل 0.01 piastre بدقة.

## النتائج

- **محرك FIFOغير موجود بعد**؛ `cost_method` مخزَّن وخامل (انظر `ADR-012`). أي سلوك له قبل ذلك سيكون وهميًا.
- **الانحراف التراكمي مستبعد رياضيًا** في المتوسط المرجح تحت تقريب السقف.
- **FIFO يستهلك بلا تقريب**، فسعره es Arithmetic أبسط من المتوسط المرجح رغم أن تتبّعه أثقل.
- **كل مؤشر مالي يُعرَّف بتعريف صريح** — قاعدة `ADR-002:35` تبقى سارية ولا يُعاد استخدام اسم بدلالة مختلفة.
- **يجب اختبار التقريب والمرتجع والخصم** قبل اعتماد المحرك المالي — شرط `ADR-002:36` يبقى ساريًا.
- **الضريبة والتكاليف المحسوبة مؤجلة** إلى الشريحة التي تملك محركاتها؛ التقريب معتمد لكن لم يُطبَّق على أي مسار بعد.
