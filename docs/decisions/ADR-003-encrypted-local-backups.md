# ADR-003: تشفير النسخ الاحتياطية المحلية

## الحالة

مقبول بقرار المالك في 2026-09-28.

## السياق

النسخة المحلية تنقل بيانات المحل المنظمة وصور المنتجات بين Windows وAndroid، وتشمل أسعار شراء وبيانات اتصال عملاء. الملف قد يغادر الجهاز، لذلك إخفاء البيانات داخل واجهة التطبيق لا يكفي لحمايته.

## القرار

- كل نسخة احتياطية قابلة للنقل مشفرة بكلمة مرور يحددها المدير، وتُفك فقط عند استيرادها مع كلمة المرور.
- الحزمة versioned وتحتوي بيانات النظام والصور وmanifest؛ تُتحقق سلامة المحتوى قبل تطبيق أي استعادة.
- كلمة المرور الخاطئة أو الحزمة المعدلة/التالفة تفشل مغلقًا، ولا تكتب فوق بيانات الجهاز المستورد.
- لا تُخزن كلمة المرور أو مفتاح فك التشفير داخل الحزمة. نسيان كلمة المرور يعني عدم القدرة على استعادة تلك النسخة؛ يجب توضيح ذلك عند إنشائها.
- صيغة envelope وخوارزميات KDF والتشفير تختار قبل التنفيذ بعد مراجعة معيارية واعتماد مكتبة مدققة وتراخيصها؛ لا يُعاد استخدام كود الاستعادة القديم لمجرد أن صيغة `.mshop` موجودة.

## البدائل التي رُفضت

### نسخة ZIP/JSON غير مشفرة

مرفوضة افتراضيًا لأنها تكشف بيانات المحل لمن يحصل على الملف.

### تشفير قاعدة SQLite المحلية في الإصدار الأول

غير مطلوب وفق مستوى الحماية الذي حدده المالك حاليًا؛ المطلوب حماية الاستخدام العادي داخل التطبيق، لا منع من يقرأ ملف القاعدة مباشرة. يمكن فتح القرار لاحقًا إذا تغير نموذج التهديد.

## النتائج

- يلزم مسار استعادة عبر Windows وAndroid واختبارات كلمة مرور خاطئة/عبث/استعادة ذرية.
- يجب فصل envelope إصدار التشفير عن بيانات JSON والصور، وإصدار صيغة backup migration عند تغيرها مستقبلًا.
- تظل الصور مستثناة من المزامنة الاعتيادية، لكنها مشمولة داخل هذه النسخة المشفرة.
