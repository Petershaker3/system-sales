## 2. Findings carried over (the first-task audit was delivered in chat only)

Goal (owner): a sales system for a mobile-phone shop — **easy, smart, fast**, desktop first, plus a mobile app.
Scored on 17 domains (0–5 each):

| System | Score | Verdict |
|---|---|---|
| Legacy (`dev_extracted/`, single-file web app) | 24/85 | broad but fragile |
| New (`review/r1-bundle`) | 22/85 | solid foundations but narrow |
| Market leaders (RepairDesk, CellSmart, Odoo POS, …) | 77/85 | reference |

Ranked gaps in the new system: desktop POS screen → IMEI units → payments & split → Arabic raster receipt + WhatsApp →
shift close → services ledger (wallets/cards/bills) → partial returns → backup UI → repairs → trade-in → reports →
LAN mobile app → labels/discounts/hold → e-receipt readiness (Egypt, Decision 281/2025).
Speed KPIs: accessory sale ≤ 5 s · IMEI phone with receipt ≤ 15 s · wallet transfer ≤ 8 s · repair intake ≤ 60 s ·
day close ≤ 3 min · launch → first sale ≤ 5 s. Details, prices and sources (R1–R80): the research report.

## 3. Owner decisions made in this session (do NOT re-ask)

**A. Approved all report recommendations** («ارفع التقريرين وموافق علي توصياتك»):
build on the new system and port legacy breadth as *specs only*; change ADR-008 so the mobile app talks to the desktop
over the **shop Wi-Fi** (desktop = source of truth; cloud later); roadmap phases 0–4; defaults for the 10 owner decisions
listed in the comparison report; simplify auth to **manager PIN + a PIN per seller**; costing = moving average +
per-unit IMEI cost.

**B. UI round 1:**
hardware = computer + keyboard + mouse + phone (**no barcode scanner** — phone camera scans);
users = owner + 1–2 sellers; **one unified sales screen** + a services button (F9);
**light and dark** themes with a toggle; shop **name, logo and colours set from Settings**;
mobile app first role = **in-shop helper over Wi-Fi**.

**C. Feedback on mockup v1 (implemented in v1.1):**
1. Categories: «عاوز باقي التصنيفات زي الاكسسوار وغيرها يكونو موجودين» → «إكسسوارات» is a main category with
   sub-categories; owner can add/rename/reorder/hide categories in Settings.
2. IMEI: «مش عاوز تسجيل imei يكون اساسي في كل شئ يكون موجود واقدر استخدمة» → IMEI **optional by default**
   (sale, receiving, inventory); a Settings switch can make it required for phones.
3. Quick switch: «في قايمة المستخدم فوق عند التأشير عليها يظهر باقي البياعين لسرعه التبديل مع الاحتفاظ بالرقم السري»
   → hover the user chip → other sellers → **PIN required** → switch; open invoice kept (see §6 Q9).
4. «لو سجلت مبيعات هتظهر في التليفون؟» → answered: yes over the shop Wi-Fi (live); outside the shop needs internet
   sync (later phase). Mockup shows a live «مبيعات النهارده» phone screen (owner: all + profit + per seller; seller: own only).
5. «هل اقدر اضيف صور للمنتجات؟ وهل ده عملي؟» → answered: yes, **optional**; most useful for look-alike accessories and the
   phone price lookup; small thumbnails (~15 KB). Implemented optional in the mockup (upload from Inventory, global hide switch).
